# 優先4項目の実装・確認記録

対象は開発ブランチの変更です。V1/V2の公開、または全アプリでの動作保証を意味しません。

| 項目 | 実装した内容 | 残る確認 |
| --- | --- | --- |
| 切替遅延・誤切替 | フォーカスイベントで監視を起こし、50ms補助監視を併用。遅いアクセシビリティ取得とイベント受信を別スレッドに分離。フォーカス世代が変わった観測・操作は破棄 | 実際の初回キー、変換中、ブラウザー同一HWND、遅いプロバイダーでの遅延・誤切替の実測 |
| アプリ別設定 | 入力欄を持つプロセスの実行ファイルのフルパスで自動／停止を指定。既定値と例外で許可リストにもできる。識別不能時はルールがあれば自動切替しない | ホスト型アプリ、管理者権限アプリ、ゲームで実際のプロセスと一致するか |
| 状態・ショートカット | 通知領域に現在の配列・入力モード・切替理由を表示。要求と確認済みを区別。Ctrl+Alt+F6〜F11から一時停止・対象配列・直前配列復帰のキーを選べる。既定では無効 | 他アプリとの登録競合、IME変換中の操作、全組み合わせの復帰動作 |
| 初回設定・入力確認 | IME選択から入力確認まで4ページのガイド。Windows UI言語に応じた日本語／英語。保存前の確認は設定ウィンドウだけで動作し、入力内容を読まない・保存しない | 100%／150%／200%表示、キーボードのみの操作、実際に入力した記号とIME変換の目視確認 |

ショートカットの既定値は Ctrl+Alt+F8（一時停止／再開）、F9（対象配列）、F10（直前配列）。
一つでも登録できなければ全部解除して通知します。手動選択は別ウィンドウへ移るまで優先し、
自動切替が直後に上書きすることを防ぎます。手動の「戻す」は実際に観測した配列へ戻す操作で、
IMEの変換モードを強制変更する操作ではありません。切替の履歴はメモリー内の現在ウィンドウ分だけです。

設定スキーマは3です。旧1/2を読み込み、ショートカットは有効にしません。
以前のバイナリーへ戻す場合は旧設定のバックアップが必要です。今回、利用者のインストール済み
設定や自動起動の設定をテストで変更することはありません。

## 自動確認

- Releaseを警告エラー化してビルド。
- 30件の回帰シナリオ：従来のメール欄修正、フォーカス世代、短い観測間隔での再試行制限、
  実行パス一致、除外／許可リスト、手動操作の保持と破棄、設定移行と不正データ。
- 日本語／英語の設定画面を表示せず構築し、保存済みの選択・アプリ別ルール・キーが読み戻されること、
  利用可能なIMEや配列がない場合に保存できないことを確認。
- ショートカットの登録先をテスト用の実装に置き換え、競合時の全解除と、競合解消後の再登録を確認。
  実際のグローバルキーはテストで予約しない。
- WindowsSmokeは独立したウィンドウだけに切替を制限。対話セッションで実行する必要があり、
  前回のフォーカス取得失敗を今回の成功として扱わない。
- サンドボックス内では有効な日本語IMEを列挙できなかった。通常のユーザーセッションでは、
  母語入力のIMM状態、英数から対象配列への切替、パスワード欄の構造情報の3項目が成功した。
- 続いて除外・一時停止・手動復帰の実機テストを追加したが、その再実行ではテストウィンドウが
  フォーカスを取得できず停止した。追加部分はビルド済みだが実機成功とは記録しない。
  ユーザー操作中の画面から強制的にフォーカスを奪ったり、Windowsの制限を変更したりはしていない。

## 手動確認手順

1. 旧版を終了し、作業用の設定バックアップを取って開発版を起動する。
2. 初回設定でIME・対象配列を選び、入力確認を開始する。通常欄と英数欄にダミー文字だけを入力する。
   他アプリへ移ると確認処理は切替を行わないこと、キャンセルで保存されないことを確認する。
3. エディターを自動、別アプリを停止に設定して保存し、両方の入力欄を行き来する。
   既定を停止にした許可リストでも確認する。
4. ショートカットを有効にし、対象配列・復帰・一時停止を試す。同じウィンドウでは手動選択を維持し、
   別ウィンドウから戻ると通常のルールになることを確認する。他アプリの既存キーとの競合も確認する。
5. [入力環境別の確認表](diagnosis.md#acceptance-matrix)を実行し、実測結果と未対応環境を記録する。

## 参照したWindows API仕様

- [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)
  — 通知スレッドでメッセージループを回す。アプリ内へのDLL注入は行わない。
- [MsgWaitForMultipleObjects](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-msgwaitformultipleobjects)
  — 待機中もイベント通知に応答する。
- [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)
  — 競合時の失敗を扱い、予約されたF12を候補から外す。
