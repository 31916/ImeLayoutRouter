# IME Layout Router の機能候補

これは開発の優先順位案です。実装済み機能や発売日の約束ではありません。
V1は日本語向けの使いやすさ、V2は検証済みの多言語対応を重視します。

## 最初に達成する品質

「入力しようとした文字を、意図した配列で入力できること」を中心に据えます。
メール欄だけでなく、同一ウィンドウ内のフォーカス移動、IMEへの復帰、変換中の
文字列、全角英数、複数アプリ間の移動を実機で確認します。現在の100ms監視では
フォーカス移動直後の最初のキーが先行し得ます。イベントを利用して検出遅延を
減らし、切替完了までの時間・誤切替・入力欠落を測ります。キーを蓄積・再送する
方法は、パスワード・ショートカット・変換中入力への影響を検証するまで採用しません。

## 優先候補

| 優先 | 機能 | 利用者の利点 | 検証・制約 |
| --- | --- | --- | --- |
| 1 | アプリ別ルールと除外設定 | エディターでは自動、ゲームでは停止などを指定できる | 手動操作を優先し、設定競合を表示する。タイトルや入力内容を記録せずアプリを識別する |
| 1 | 状態・切替理由の表示 | 今のIME/配列、切替理由、未対応状態がわかる | 「切替要求」と「切替完了」を区別する。表示は任意で入力を妨げない |
| 1 | 手動切替・一時停止のショートカット | マウス操作なしで元に戻したり停止できる | Windows/他アプリとの競合を検出し、変換確定や既存ショートカットを壊さない |
| 1 | 初回設定ウィザードと確認用入力欄 | 対象IME・配列を選び、メール記号などをその場で確かめられる | 物理キーの刻印から配列を勝手に推測しない。ローカルのダミー入力だけで確認する |
| 2 | IMEごとの復帰設定 | ひらがな・カタカナ・半角英数・ハングルなど、戻り先を選べる | 現在の言語ID単位の制御から、個別IME識別が可能か調査する。全IMEで可能とは約束しない |
| 2 | 中国語・韓国語の実機対応とアプリUI翻訳 | 日本語以外の利用者も同じ問題を解決できる | Pinyin/Bopomofo/Koreanの変換・候補選択・英数復帰を個別検証。翻訳とIME対応は別に管理する |
| 2 | 設定の書き出し・読み込みと復元 | 複数PCで使い慣れた設定を再利用できる | インストール済みIMEやHKLが異なるため、読み込み時に再照合する |
| 2 | 署名付き配布・更新通知・戻せる更新 | 導入元を確認し、問題時に前の版へ戻せる | 実行ファイルの署名と更新元・成果物の検証を行う。自動適用は明示的な設定にする |
| 3 | キーボードごとの設定 | 内蔵JISと外付けUSなどの使い分けを助ける | デバイス識別と入力配列の切替は別問題。同時入力・切替タイミングを検証する研究課題 |
| 3 | ARM64・リモート環境の対応 | Windows ARM機やリモート作業でも使いやすくする | x64版の成功をそのまま各環境の対応実績にしない |

一時停止・診断ログ・複数CJK言語の選択は現在の開発版に既にあります。上の候補は、
それらの使いやすさや検証範囲を広げるものを含みます。「全員に対応」は長期目標とし、
公開時には確認済みのWindows・IME・アプリの組み合わせを明示します。

## 技術上の調査入口

- [Microsoft TSF](https://learn.microsoft.com/en-us/windows/win32/tsf/text-services-framework)
  は高度な多言語入力の基盤です。ただし、外部の常駐プロセスから他アプリの
  個別IME状態をすべて取得できることを意味しません。現行方式との比較調査が必要です。
- [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)
  はシステム全体のホットキーを登録できます。予約キー・登録競合を考慮します。
- [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)
  は複数入力デバイスを扱う調査入口です。デバイスの検出だけでアプリへの配列適用が
  解決するわけではなく、キー内容の保存を前提にしません。
